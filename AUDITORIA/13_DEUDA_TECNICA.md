# Deuda técnica

Prioridad alta: límites de confianza, acceso directo a datos desde UI, dos arquitecturas de backend, DDL no versionado originalmente y ausencia de tests.

Prioridad media: clientes Supabase duplicados, consultas repetidas, validaciones solo UI, convenciones de rol/esquema inconsistentes, errores absorbidos devolviendo arreglos vacíos desde IPC.

Prioridad baja: imports/dependencias sin uso, documentación desactualizada, capitalización inconsistente de archivos y CSS, Bootstrap cargado dos veces en algunas vistas.

No se recomienda una reescritura. La deuda debe reducirse siguiendo el plan P0-P3 y manteniendo pruebas de caracterización.
